Changelog

What shipped, what changed and what is still missing. Newest first. Items under Unreleased are planned and are not in any download; everything under v0.1 exists in the public scaffold today.

v0.1~3 min read

The project is at v0.1: a working scaffold rather than a finished product. Versions below list behaviour, not intentions, and the Known issues subsection is part of the release rather than a disclaimer added later.

Unreleased

Planned, not shipped

Nothing in this section is in the current download. There is no branch to enable it, no hidden flag and no date. Treat it as direction, and check the release notes of an actual version before relying on any of it.

Planned

  • Survey walking: tap-to-place points, 15-second samples, pause/cancel/redo and blind scoring.
  • Heatmaps: IDW, kriging, signal-gap, confidence and sticky-client layers, with a floor selector and per-band filtering.
  • Propagation model: path-loss fit, per-wall losses, calibration against measured points and a held-out RMSE reported in the UI.
  • Live position: kNN fingerprint matching, smoothing, and the /api/v1/position/* endpoints.
  • UniFi polling: AP inventory, radio configuration and client associations from the controller the wizard already knows about.
  • Tuning engine: rule-based recommendations with dry-run, one change at a time, guardrails and rollback.
  • Model import extras: semantic-node path, add-on scan merging (2D chamfer plus ICP with a fit score) and the in-browser confirm, label and material editors.
  • A Windows agent using the native WLAN scan API, a macOS server install path, a published container image, a per-band 6 GHz heatmap view, and an Omada integration with the same read-only constraint.

v0.1 — scaffold

The first public release. One server process on port 8800, one SQLite database, one reading schema shared by three node types, the deterministic model-import pipeline and this documentation. No cloud account, no telemetry and no network listener other than the web port. The survey and modelling engine is not in this release — see Known issues.

Added

  • Installer for Debian, Ubuntu, Fedora and Arch, plus a local Docker build. Installs to /opt/wifi-survey, keeps data in /var/lib/wifisurvey, runs as wifi-survey.service under the wifisurvey user.
  • Config at /etc/wifisurvey/config.toml (mode 0640) with a generated viewer_token and pairing_secret, and a first-run wizard for the admin password, model upload, floor names and optional AP setup.
  • Model import pipeline (modelkit) for GLB, glTF and OBJ: unit and up-axis checks, floor detection, wall-line extraction, regularisation, and a rebuilt model with floor plans and metadata written locally.
  • Three scanner agents — Linux (stdlib), Android/Termux and ESP32 — posting the same version 1 payload to /api/v1/readings and /api/v1/scans.
  • Pairing with a six-digit single-use code valid for 10 minutes, claimed through POST /api/v1/pair, with per-node tokens that can be revoked individually.
  • Browser viewer: three.js model, floor list, AP placement with history, and a server-sent event stream for live updates.
  • This documentation site: hand-written HTML, offline search, no external assets.

Changed

  • Readings from all three node types use one schema, replacing the per-platform payloads used during development.
  • Configuration, the viewer token and the pairing secret live in one config.toml; there is no separate token file.
  • The default port is 8800 for both UI and API on one origin, with --port as an override.

Fixed

  • Token comparison happens in constant time, and a revoked node token is rejected with 401 rather than being accepted until restart.
  • Readings with timestamps more than 60 s away from server time are rejected at ingest, which stops a node with a dead NTP client from writing points into the past.
  • Model import rejects archives with a nested folder instead of importing an empty scene.

Known issues

Known issues in v0.1

  • No survey screen, heatmaps, propagation calibration, live position, UniFi polling or tuning engine. Readings are stored and listed; nothing models them yet.
  • No published container image (build it from installer/Dockerfile), and no Windows or macOS server install.
  • No Windows or macOS agent. Scanner nodes are Linux, Android and ESP32 only. iOS cannot scan.
  • 6 GHz is recorded when the adapter reports it; there is no per-band heatmap view yet.
  • The ESP32 node is 2.4 GHz only and its sensitivity is not comparable with a laptop radio.
  • No TLS. The viewer token crosses the LAN in plaintext, so the network is the security boundary.
  • Upgrades are manual (installer/install.sh --upgrade); there is no doctor or support-bundle command yet.
