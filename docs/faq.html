FAQ

Short answers to the questions that come up before and after a first survey. Each answer links to the chapter that covers the detail; if your question is about something broken rather than something unclear, start with Troubleshooting.

v0.1~6 min read

General

Do I need UniFi gear, or does it work with Omada, Eero and consumer routers?

No. Wi-Fi Survey is vendor-neutral: the survey itself only needs a device that reports BSSIDs and RSSI, which every laptop and phone does. UniFi is an optional read-only integration that adds AP inventory and radio configuration; without it you place access points on the map by hand. Omada, Eero, consumer routers and mixed setups all work for surveying, and you can record AP details manually. See UniFi integration for what the integration does and does not read.

How many access points can it handle?

A single instance comfortably covers a home or a small office with a handful of APs. Each survey point can hold every BSSID it sees, and the propagation model is computed per AP and per floor, so the practical limit is your patience for walking rather than a hard cap in the code. Very large sites are out of scope for v0.1 — there is no multi-site management and no controller-scale inventory. Concepts explains how APs are attached to a survey.

Does it run on a Raspberry Pi?

Yes. A Raspberry Pi 4 with 4 GB of RAM is enough for up to about five floors: the server is a small FastAPI process with SQLite, and heatmap interpolation is the heaviest work it does. Importing a large model and rendering kriging on a big floor is where a Pi feels slow, not during a survey. Install it like any other Debian-family host — see Install — and expect the model import step to take noticeably longer than on a desktop.

Hardware

Which phone or laptop should I use as a scanner?

Any Linux laptop with NetworkManager is the best scanner, because the agent reads real scan results without platform throttling. Android works well through Termux and is the most convenient for walking around. iPhones are not supported as nodes. The device that surveys does not have to be the device that views the map — the UI runs in any modern browser. Scanner nodes compares the three node types.

Does the phone need to be rooted?

No. The Android node uses the standard scan results the platform exposes to apps, which needs no root and no special permissions beyond location, since Android gates Wi-Fi scanning behind it. The trade-off is that Android throttles scans and returns cached results more aggressively than Linux, so points take a little longer to settle. Root would allow raw monitor-mode captures, which this tool does not use.

How far does an ESP32 node reach?

An ESP32 node is a 2.4 GHz scanner only, so treat it as a fixed sensor for one band rather than a walking survey tool. It is useful for a permanent check on one room or for confirming a dead spot, not for mapping a floor. Its antenna is small and its sensitivity is worse than a laptop's, so its absolute dBm values are not directly comparable with other node types. See Scanner nodes for the capabilities of each type.

Data

Where is my data stored?

Everything lives in /var/lib/wifisurvey on the machine you installed it on: survey.db for readings, APs and nodes, and models/ for imported geometry. Configuration is a separate file at /etc/wifisurvey/config.toml (mode 0640); the viewer token and pairing secret are inside it under [security]. Nothing is written anywhere else and nothing is uploaded. Privacy lists every field that is kept.

Can I export a survey, and in what format?

Not yet. CSV and JSON export from the survey page are planned: CSV one row per BSSID observation with timestamp, floor and position, JSON the nested schema the agents post with. In v0.1 the data is in SQLite, so sqlite3 /var/lib/wifisurvey/survey.db (or a copy of the file) is the export path. Models are never part of an export; copy models/ if you need the geometry.

Can I delete a survey, and do I need my own backups?

Deleting a survey removes its readings, its heatmap cache and any AP placements attached to it, immediately and without a recycle bin. You do need your own backups: there is no cloud copy and no automatic snapshot. Stopping the service and copying survey.db plus models/ gives you a consistent backup, since the database runs in WAL mode. See Privacy for what a delete leaves behind.

Accuracy

Why doesn't the heatmap match my speed test?

Signal strength is not throughput. A heatmap predicts RSSI, and RSSI says nothing about your internet plan, your AP's backhaul, channel congestion, airtime sharing or the speed of the server you tested against. A room at −65 dBm can be fast on an idle 80 MHz channel and slow at 8 pm. Use the map to find coverage and roaming problems, and a throughput test to measure bandwidth. Heatmaps explains what each view actually shows.

Why is 5 GHz so much shorter than 2.4 GHz?

Higher frequency means more free-space loss and worse penetration through walls and floors — the model uses 40.2 dB at 1 m for 2.4 GHz against 46.4 dB at 5 GHz, and every wall adds more on 5 GHz. That is physics, not a fault in the AP. The practical result is that 5 GHz covers a room well and dies at the far end of a floor, which is exactly what a per-band heatmap is for. See Propagation model.

Why does my phone show a different dBm than my laptop?

Different radios, different antennas and different drivers. A phone held in your hand is also detuned by your body, and Android reports rounded values from a cached scan. Absolute numbers therefore differ by several dB between devices, and the survey converts NetworkManager's percentage scale to dBm with a fixed formula that is only accurate to about ±3 dB. Compare trends within one device rather than across two. Scanner nodes covers the details.

Operations

Does it need an internet connection?

No. Installation needs to fetch packages once, and after that the server, the UI and the agents all run on the LAN. There is no licence check, no update ping and no telemetry. The docs site is static files with no CDN, so it works offline too. The one exception is the optional UniFi integration, which talks to your controller on the local network and never to the internet.

Can I expose it to the internet?

Not recommended. There is no TLS by default, authentication is a single bearer token, and the presumed security boundary is the LAN. Port forwarding puts a plaintext admin interface on the public internet. If you need remote access, put it behind a VPN you already trust — WireGuard or your router's built-in server — and leave the survey port closed from outside. Privacy describes the listeners and what they require.

Can I use it for more than one house?

Not in v0.1. The server holds one model with its floors, APs and readings; separate surveys with per-survey export and delete are planned. Multi-site management — per-site users, a central roll-up, remote agent enrolment across networks — is further out. Running a survey describes the intended model.

How do upgrades work, and what licence is it under?

Upgrades are manual: pull the repository, run installer/install.sh --upgrade, and it repairs the virtual environment, runs pending schema migrations in a transaction and restarts the unit. Check the result with systemctl status wifi-survey and journalctl -u wifi-survey; a wifi-survey doctor command is planned. The licence is MIT — see LICENSE in the repository. Changelog lists what changed between versions.

Not supported in v0.1

iOS as a scanner node, a Windows or macOS server install, cloud sync and multi-site management are all absent. 6 GHz works only where the adapter and driver report it. If a question here assumes one of them, the honest answer is that it does not exist yet — see Changelog for what is planned rather than shipped.
