Quickstart

This is the shortest path to a heatmap you can look at: one server, one floor, one access point, five measured points. It is deliberately small. The result tells you that the whole pipeline works, not whether your Wi-Fi is good — that takes a real survey, which is a longer walk.

v0.1~8 min read

v0.1 scope

This page describes the intended end-to-end flow. In v0.1 you can install the server, import a model, pair a node and collect readings; the walking/survey screen, the heatmap renderer and the propagation model are planned and not in this release. Steps that depend on them say so.

Before you start

Have these ready, or the ten minutes stretch into an evening:

  • A Linux host with systemd and root access, on the same LAN as your access point. See Install for the exact list.
  • The viewer token the installer prints. It is stored as [security] viewer_token in /etc/wifisurvey/config.toml.
  • A laptop with Wi-Fi on that LAN, or an Android phone, to act as the first scanner node.
  • Either a 3D model of the floor, or a rough width and depth in metres. A rectangle is a legitimate starting point.
  • Five to ten minutes of walking, and the knowledge of where your AP physically sits.

If you do not know the AP's position, look at the label or the switch port. Guessing its corner wrong tilts every model that follows.

The ten-minute path

The five steps below are the same order the UI is arranged in: map, APs, nodes, survey, heatmap. Do not skip ahead — each step writes something the next one reads.

  1. Install the server and open the UI

    Run the installer on the host that will keep the data, then open the URL it prints and paste the token once.

    git clone https://github.com/jpullen724-stack/wifi-survey.git
cd wifi-survey
sudo installer/install.sh

    Browse to http://survey.local:8800, or http://<SERVER_IP>:8800 if mDNS is unavailable, and paste the token. The browser stores it and stops asking.

    You should see an empty dashboard: zero models, zero floors, zero nodes, and a service status line with a recent uptime.

    If it fails: the page does not load, or the token is rejected — see Troubleshooting before changing anything in the config file.

  2. Import a model, or draw a rectangle

    Go to Models → Import and drop a .glb, .gltf or .obj (150 MB per file; archives are not unpacked in v0.1). If you have no scan yet, choose New floor → Rectangle and enter width and depth in metres.

    You should see the floor outline in the viewer and a confirm list of detected walls. With a rectangle there is nothing to confirm — you get four walls and a ceiling height.

    If it fails: the importer rejects the file, finds no floor, or the walls land in the wrong place — see 3D model import, or Troubleshooting for upload errors.

  3. Place at least one access point

    Open Access points → Add. Give the AP a name, pick its band and channel, and click its real position on the floor plan. Coordinates are metres from the floor origin, so the click is the measurement.

    You should see an AP marker with a translucent coverage ring, and the AP in the list with a channel and a transmit power.

    If it fails: the marker will not stick to the floor, or the channel list is empty — that usually means the floor has no elevation data. See Troubleshooting.

  4. Pair a node and take five points

    On the server, print a pairing code; on the scanning machine, claim it. Then post a reading from each spot you want measured — in v0.1 with the agent's fixed position setting, or by letting the node send its configured coordinates.

    # on the server
sudo -u wifisurvey -H /opt/wifi-survey/venv/bin/wifi-survey pair   # six digits, 10 minutes

# on the laptop: copy the stdlib agent and pair it with that code
./agent-linux/install.sh --server http://survey.local:8800 \
  --pair-code 123456 --node-id laptop-hall

    Once paired, the agent scans every 10–15 s and posts each burst with the position you give it. In v0.1 the survey screen itself is not built: the server stores readings and lists recent scans, and the node shows a heartbeat under Nodes. The tap-to-place walking workflow is planned.

    You should see the node under Nodes with a last-seen timestamp, and readings appearing in the recent-scans list.

    If it fails: the node never appears, the code is rejected, or the sample count stays at zero — see pairing and Troubleshooting.

  5. Open the heatmap — planned

    Heatmaps (IDW, kriging, confidence and gap views) are part of the survey engine and are not in v0.1. The intended first look is: Heatmaps, pick the floor, pick the AP you placed, leave the method on IDW. The blended view mixes measured points with the model estimate.

    Target behaviour is a coloured surface that is strongest near the AP and falls off with distance, plus a coverage percentage and a legend in dBm. Read Heatmaps for the method the release will use.

What the first map is worth

Five points is a smoke test, not a survey. Interpolation needs neighbours on all sides of a cell; with five samples most of the floor is extrapolation, and the map will show confident-looking colour where there is almost no evidence. The coverage percentage from this run should not be quoted to anyone.

The real minimum is 10–15 points per floor, and 20–25 if you want a model that predicts rooms you did not walk through. Read Running a survey for the walking pattern that gets you there, and accuracy expectations for what the numbers are allowed to mean.

Known limitation

A five-point run cannot produce a calibrated propagation model. Calibration needs enough spread to fit path loss and wall multipliers, and a held-out error from five points means nothing. The model view stays empty until the run has enough points to fit.

From five points to a real survey

Keep the same model, APs and node, and add points to the same run instead of starting over. The practical loop is: walk a room, tap, wait for the sample, repeat. Aim for a grid with points every 4–6 m and one point in every room you care about, plus one just outside each exterior wall if you want to see leakage.

Two habits make the difference between a usable map and a pretty one. First, hold the device the same way at every point — body absorption is worth several dB. Second, do not sample while walking: the 15-second window averages over motion and lands somewhere you were not standing.

Take a baseline first

Before you change any AP settings, finish one complete run. Tuning recommendations compare against a baseline; without one, a later "improvement" has nothing to be measured against. See Tuning recommendations.
