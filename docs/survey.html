Running a survey

A survey is a sequence of measured points. Each one is a 15-second sample taken where you clicked on the plan, and the quality of everything downstream is decided here: which access points are modeled, and where you chose to stand.

v0.1~7 min read

Planned — not in v0.1

Guided survey walking is not implemented yet. v0.1 accepts and stores readings from a paired node using the position the agent sends, and lists recent scans. The survey screen described here — resume a run, place the pin, sample, pause/cancel/redo and blind scoring — is the intended design, not current behaviour.

Before you start

Five things have to be true before the first point. Each is quick to check now and annoying to discover an hour later.

  • Model imported and confirmed. The walls in the model are the walls it charges loss for. A wardrobe still in the plan makes every reading disagree with the map.
  • Access points placed. Band, channel, width and power must match what the radios are configured with; stale settings compare two different networks.
  • Node paired. It shows under Nodes with a recent last-seen time. See Scanner nodes for each type.
  • Clock synced. Server and node both on NTP. Timestamps order samples and decide staleness, so a node an hour behind produces a survey that lies about its age.
  • One floor at a time. A sample belongs to a floor; switching mid-pass is how points land on the wrong level.

The server listens on http://survey.local:8800 and serves UI and API from the same origin, so a node on the LAN needs no second hostname and no CORS exception.

Placing access points

Open APs and add one row per radio. A dual-band AP is two rows sharing a position, because channel and power are set per radio.

FieldWhat it meansNotes
x, yPosition in metres in model coordinatesClick the plan to fill both; typed values are rounded to 1 cm
floorFloor index, 0 = lowestAPs on a floor you have not modeled cannot be placed
heightMounting height above the floor1.5–2.5 m; ceiling AP 2.4 m, desk unit 1.0 m
band2.4 or 5 GHzOne row per band
channelOperating channelMust match the radio, not the plan
widthChannel width in MHz20, 40 or 80; a 20 MHz channel on an 80 MHz radio models the wrong noise floor
tx_powerTransmit power in dBmWhatever the radio reports, not the regulatory maximum

Manual entry is the default and the only option for hardware the tool cannot log into. The UniFi import reads APs, radios, channels and widths from the controller — see UniFi import. Imported rows are ordinary rows: correct anything the controller reports wrongly, because the survey trusts the table, not the controller.

Every edit creates a placement revision, and each survey records the one it was taken against. Move an AP and both maps stay readable: the old one still describes the network it measured, and the pair becomes a before-and-after.

The I'm-here flow

Position comes from one input: you. There is no inertial tracking and no assumption that you walked in a straight line from the previous point, so the tool cannot notice that you went into the kitchen instead of the hall.

  1. Select the floor. The plan shows only the level you are surveying.
  2. Click your position. A marker appears with its coordinates; drag it if the click landed badly.
  3. Confirm. The node starts sampling immediately. A wrong position is free to fix before confirming and expensive afterwards.
  4. Watch the sample. The panel counts scans and lists BSSIDs as they arrive. If the count stays at zero, the node is not scanning — check its status rather than waiting.
  5. Repeat. Walk 2–3 m, click, confirm. The point list grows with RSSI for the strongest AP at each spot.

What a sample is

Fifteen seconds of scans, not a single reading. The window exists because a scan pass takes time: nmcli enforces roughly 10 s between rescans, so 15 s buys one full pass, sometimes two, across the channel list. Shorter windows risk a sample built from a scan that started before you arrived.

Each scan reports BSSID, SSID, band, channel, centre frequency and RSSI in dBm. Nodes that only expose a percentage are converted on the server: dBm = -100 + 0.6 × pct, clipped at −40, with about ±3 dB of assumed error — which is why a percentage-only node yields a coarser map.

curl -sS -X POST http://survey.local:8800/api/v1/readings \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "node_id": "node-laptop-01",
    "ts": "2026-03-14T18:22:05Z",
    "position": {"x": 4.1, "y": 2.7, "floor": 0},
    "samples": [
      {"bssid": "bssid-one", "ssid": "example", "band": "5",
       "channel": 36, "freq_mhz": 5180, "rssi": -58},
      {"bssid": "bssid-two", "ssid": "example", "band": "2.4",
       "channel": 6, "freq_mhz": 2437, "rssi": -71}
    ]
  }'

The UI posts to the same endpoint, so a script that sends readings is indistinguishable from a node. One sample carries many BSSIDs on purpose: a single position measures every AP audible there.

Two passes beat one long walk

Do a coarse first pass — one point per room, five minutes — then open the heatmap and let it tell you where it is guessing. The second pass only densifies those areas. Walking a whole floor at full density before looking at any output usually means re-walking the wrong places.

How many points

Ten to fifteen points per floor is the minimum for a usable map. Twenty to twenty-five is where the model becomes worth calibrating, because the fit then has enough spread to separate wall loss from distance.

Floor areaPointsWhat it looks like
≤ 40 m²8–10One room plus its doorways; every corner gets a point
40–80 m²12–15Two or three rooms; both sides of each internal door
80–150 m²18–25Whole flat; corridor gets points every 2–3 m
> 150 m²25–35Split long runs by room; do not thin out the far end

The rule that matters more than the count: one point every 2–3 m along walkable paths, plus every room corner and both sides of every doorway. Points cluster where people walk, which is also where the map is read.

Recording tips

  • Chest height. Hold the device at 1.2–1.4 m, where a laptop or phone actually sits. Sampling at desk height and reading the map at standing height mixes two paths.
  • Do not cover the antenna. Hands around a laptop lid or a phone's top edge cost several dB every time — consistently enough to look like a wall.
  • Stand still while sampling. A window taken mid-stride averages the path instead of measuring the point.
  • Sample both sides of every doorway. That is the largest gradient in a house and the weakest place for interpolation.
  • Stay out of cupboards. A point inside a closed cupboard measures the cupboard, and it will look like a dead zone forever.
  • Repeat the worst spot three times. Three readings within 3 dB means the number is real; a 10 dB spread means something moved, so re-take rather than average.

RSSI moves on its own

The same spot can read 5 dB apart a minute later with nothing changed, because the client radio, the AP's rate adaptation and whatever else is on the channel all shift. Do not chase single points. Judge a floor by the pattern across ten of them, and re-sample rather than editing a number by hand.

Editing and redoing points

Points stay editable, and the three operations do different things:

  • Move corrects a mis-click. It changes where the readings plot and re-runs interpolation, but re-measures nothing. Move by tens of centimetres, not across the room.
  • Re-sample replaces every value at that point with a fresh 15 s window. Use it when the environment changed or the first sample looked wrong.
  • Delete removes the point from the current survey. The revision history keeps it, so restoring an earlier revision undoes it.

Fifteen seconds is a floor, not a suggestion. Shorter samples are discarded by the server rather than extrapolated, because one partial scan cannot separate real signal from a scan that landed between beacons. If a node disconnects mid-sample, the point is marked incomplete and contributes nothing until it is re-taken.

What makes a survey stale

A survey describes a radio environment at a moment. Change the environment and the map still renders perfectly while describing nothing.

TriggerWhat to redo
An AP movedRe-survey the affected floor; keep the old revision
Channel or width changedRe-survey; interference per channel does not transfer
Transmit power changedRe-survey; every RSSI shifts with the power delta
Model re-imported or walls relabelledRe-run calibration; re-survey if geometry moved
AP firmware updateSpot-check 3–5 points per floor; over 4 dB means full re-survey
Furniture or layout changedRe-survey affected rooms; metal changes more than soft furnishing
More than 90 days oldFull re-survey, even with nothing knowingly changed

The survey list shows each survey's age and AP revision, so a map taken before the last channel change is labelled as such rather than mixed with newer data.

Points are moments, not monitoring

Nothing re-measures between surveys. A link that fails only under load, or only while the microwave runs, will not appear here: a 15 s window is quiet by construction. Survey the spot repeatedly at the time it happens and compare the repeats.

With points on the floor, open Heatmaps to read what they add up to, or go straight to the propagation model if you want the wall-aware fit behind them.
